# 발표 자료에 사용할 근거와 표현

발표 PPT 자체는 이 작업에서 제작하지 않았다. 아래는 실제 구현과 실험 자료를 슬라이드로 옮길 때 사용할 수 있는 내용이다. 수치의 출처·조건·실패도 함께 보여준다.

| 심사 기준 | 설명할 내용 | 근거 |
|---|---|---|
| 문제 정의 | 자연어의 “한 번”, “하루”, “필수”, “피하고 싶다”를 한 덩어리 취향 문자열로 저장하면 의미가 소실되는 문제 | 실제 입력 UI와 원자 조건 규격; 사용자 효과 조사는 미실행 |
| 아이디어 | 같은 입력을 서로 다른 모델이 독립 분석하고, 서버의 근거 검사와 의미 비교로 일치·보류·장애를 구분 | ensemble.py, atomic_preferences.py; 독창성/시장 우위 주장은 별도 조사 필요 |
| 구현 | 추가 필수 질문 없이 같은 화면에서 정리·직접 수정·저장·확정·복원; 원문·기기·버전 경계 유지 | FE 화면 검수, SQLite HTTP, 실제 제공자 focused smoke |
| 기술 이해 | Qwen만 LoRA 학습; Gemini는 외부 API. 그룹 집계는 결정적 코드. 장소/경로 최적화는 별도 담당 | 학습 manifest, 세 저장소 코드, 인수 경계 문서 |
| AI 활용 | 고정 형식만 검증하는 규칙과 자연어 의미를 해석하는 모델의 역할 분리 | 데이터·프롬프트·모델 revision·SHA 및 오류 사례 |
| 품질 검증 | 기반/학습 Qwen, Gemini v2, 조합을 동일 test로 비교. v1은 granularity 차이로 F1 비교 제외 | RESULTS.md와 원자료 JSON/CSV |

## 입력부터 저장까지

1. FE가 본인 원문과 공통 조건 버전을 저장한다.
2. BE가 권한·CV/PV·멱등성을 확인하고 같은 입력을 두 제공자에 병렬 전달한다.
3. 각 출력의 형식·연속 원문 근거·숫자·강도를 검증한다.
4. 같은 의미 조건은 적용하고 차이/누락은 unresolved에 보존한다. 한 모델 장애는 degraded로 구분한다.
5. FE가 같은 화면에 조건을 표시한다. 사용자의 수정은 user 출처로 저장한다.
6. BE가 분석 영수증과 현재 버전을 대조하고 본인이 직접 확정한다.
7. 확정된 현재 조건만 비공개 단체 인수 자료로 집계한다. 정확한 제약의 경로 적용은 별도 연동이다.

## 팀 구현과 외부 기술 구분

직접 구현: v2 원자 계약·근거 검증·합의/보류 정책·학습 데이터 생성/분리·completion-only LoRA 학습 루프·CPU 공유 head 배치·평가/manifest·FE 리뷰 UI·BE 저장/영수증/버전·그룹 집계·패키징.

외부 기술: Qwen 사전학습 가중치와 tokenizer, Gemini API, PyTorch·Transformers·PEFT, CUDA·Triton/FLA, FastAPI·SQLAlchemy, React/Vite, Docker/Caddy 등 기존 서비스 구성. 기반 모델을 처음부터 학습했다고 표현하지 않는다. 두 모델을 함께 학습하거나 스태킹한 구조도 아니다.

## 수치를 말할 때

“합성 family 분리 test에서 학습 Qwen의 엄격한 조건 일치 F1은 4.7%→46.8%였다. 조합은 정밀도 80%, 재현율 33.3%로 보류가 많았다”라고 조건을 붙인다. “사용자 정확도 80%”, “Gemini보다 우수”, “모든 필수 조건 보존”, “모호한 입력을 해결”이라고 표현할 근거는 없다.

현재 사람 정답은 0개다. 독립 입력·별도 검수자·외부 처리와 재배포 허가가 준비되면 human 전용 test로 평가한다. 실제 사용자 검수 기록은 HUMAN_ACCEPTANCE.md에 사람이 작성한다.

## 시연 자료

- 화면: reports/ui의 PC/모바일 캡처와 범위 설명.
- 모델: 기반 revision, adapter SHA-256, 학습 로그와 manifest.
- 정상 흐름: 두 실제 모델이 응답한 focused BE 왕복 기록.
- 실패 흐름: 공통 숙소 희망을 예약처럼 추출했을 때의 거절, 두 모델 해석 차이, stale 영수증.
- 제출: 코드 main SHA·adapter 다운로드·checksum·재현 명령이 필요하다. IP/컨테이너 ID만으로 모델을 제출하지 않는다.

Docker/GPU 컨테이너와 운영 MySQL·배포 URL·사람 인수는 미검증으로 표시한다. 공개 업로드와 PR 병합은 별도 절차다.
