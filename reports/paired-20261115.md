# Gemini 단독과 두 Qwen 앙상블의 동일 조건 비교

2026년 11월 15일, 운영 LoRA 어댑터와 추가 학습 후보를 동일한 추론 환경에서 비교했다. [이전 비교](continued-20261115.md)의 실행 환경 차이와 운영 앙상블의 측정 공백을 보완했다. [원자료](paired-20261115-test.json)에 합성 입력·정답·최종 출력과 실제 Qwen·Gemini 응답을 함께 보존했다.

Gemini 단독 기준선도 두 조합에 공유했던 동일한 최초 응답 26개로 계산했다. 실제 서비스의 Gemini 단독 모드 검증·후처리를 적용했고, 이 기준선 추가에는 모델 재호출이 없었다. 이전 별도 실행의 Gemini 점수를 섞지 않았다.

## 데이터와 평가

| 구분 | 전체 합성 데이터 | 학습 | 모델 선택용 검증 | 시험 |
| --- | ---: | ---: | ---: | ---: |
| 기존 LoRA 어댑터 | 205건 | 168건 | 11건 | 26건 |
| 추가 학습 후보 | 217건 | 180건 | 11건 | 동일한 26건 |
| Gemini API | — | — | — | 동일한 26건 |

Gemini의 대시는 외부 API 활용을 뜻하며 이 데이터로 가중치를 직접 학습하지 않았다. 프롬프트·출력 규격을 설계하고 같은 시험으로 평가했다.

이번에는 재학습하지 않았다. 후보는 기존 학습 168건에 신규 합성 예시 12건을 더해 학습했던 어댑터다. 두 데이터 파일의 시험 레코드·정답이 동일함을 확인했다. 시험에는 9개 사례 묶음, 정답 조건 24개, 필수·제한 조건 7개, 예약 2개가 있다. 사람의 비공개 요청·평점과 학습·검증용 입력은 이 시험에 포함하지 않았다.

기존 `evaluation.metrics`로 대상·선호/회피·중요도·근거 종류·범위·대상자·횟수·수량 등의 조건 구조를 비교했다. 공백·대소문자를 정규화하며 의미가 비슷한 다른 표현까지 자동 정답 처리하지 않는다. 정밀도·재현율·F1은 조건을 합산한 micro 지표다. 실패 사례도 전체 26건과 누락 계산에 포함했다. 유효 출력은 서비스 결합·검증 절차가 최종 조건 구조를 반환했는지 나타낸다.

## 같은 조건으로 실행한 방법

- 한 Linux Docker 평가 프로세스에 두 어댑터를 로드하고 하나의 Qwen3.5-4B 기반 모델·토크나이저를 공유했다. 활성 어댑터만 바꾸며 문장마다 실행 순서를 교대했다.
- RTX 4080 SUPER, Python 3.12.3, Torch 2.9.1+cu128, Transformers 5.23.0, PEFT 0.21.3을 사용했다. 기반 모델 revision은 `851bf6e806efd8d0a36b00ddf55e13ccb7b8cd0a`다.
- batch size 1, greedy decoding, thinking 비활성화, 입력 최대 4,096토큰, 출력 최대 2,048토큰, Qwen 요청 제한 60초, seed 20261115로 고정했다.
- `gemini-3.5-flash-lite` 최초 응답을 문장당 한 번 받아 두 조합에 공유했다. 재검토 요청도 내용이 같으면 응답을 공유했다.
- 두 조합의 재검토 요청을 먼저 수집·호출한 뒤 네트워크 호출 없이 실제 `interpret_personal_draft_v2`로 최종 점수를 계산했다. API 지연이나 처리 순서로 한 조합만 재검토를 놓치는 영향을 줄였다.
- Gemini 호출은 최초 분석 26회와 서로 다른 재검토 5회로 총 31회였다. 일시적 HTTP 429·5xx만 재시도하도록 설정했고 이번 실행에는 재시도가 없었다. 형식·의미 검증 실패는 재생성하지 않고 점수에 포함했다.
- 운영 컨테이너와 별도의 임시 평가 컨테이너를 사용했다. 운영 서비스도 같은 GPU에 함께 있었고 첫 호출의 커널 초기화가 포함돼 있어 이번 기록으로 운영 지연·처리량 우열을 판단하지 않는다. 두 Qwen 모두 시간 제한 초과는 없었다.

## 점수 차이와 실제 실패

### 이전 Gemini 단독 44.9%와 이번 36.0%의 차이

| Gemini 단독 실행 | 유효 출력 | TP / FP / FN | 정밀도 | 재현율 | F1 |
| --- | ---: | --- | ---: | ---: | ---: |
| 이전 추가 학습 보고서의 별도 실행 | 23/26 | 11 / 14 / 13 | 44.0% | 45.8% | 44.9% |
| 이번 공유 응답 기반 실행 | 25/26 | 9 / 17 / 15 | 34.6% | 37.5% | 36.0% |

입력·정답 26건, 추출 프롬프트, JSON 출력 규격과 조건 일치 채점식을 유지한 상태에서 Gemini API를 별도로 호출해 받은 응답이 달라졌다. 이전 보고서 커밋 이후 원자 조건 검증·예약 검증·Gemini 요청 코드와 기존 채점 코드에 변경이 없음을 확인했다. 이번 응답을 기존 `_validate_raw`와 `score_output` 경로로 직접 계산해도 TP 9, FP 17, FN 15와 F1 36.0%가 일치했다. 새 기준선의 후처리 경로를 추가한 것 때문에 점수가 낮아진 결과로 해석하지 않는다.

예를 들어 이전 공개 사례별 결과에서는 박물관 회피와 전통 시장 방문의 두 조건이 모두 일치했지만, 이번 Gemini 단독 출력은 박물관 회피의 중요도를 `unspecified`로 반환해 정답 `preferred`와 달랐다. 칼국수 요청의 한 번도 목표 횟수 `target` 대신 정확 횟수 `exact`로 반환해 엄격한 구조 일치 점수에 영향을 줬다. JSON 형식·근거 검증을 통과한 응답 수가 늘어도 조건 일치 점수는 내려갈 수 있다.

이번 비교의 seed·greedy 설정은 로컬 Qwen에 적용했다. Gemini API 요청은 temperature·seed를 별도로 고정하지 않았고, 모델 이름은 같은 `gemini-3.5-flash-lite`를 사용했다. 이 기록만으로 외부 제공자의 내부 모델 변경 여부나 반복 호출 변동의 세부 원인을 확정하지 않는다. 기존 44.9%와 새 앙상블 수치를 한 실행의 비교표로 섞지 않고, 같은 응답을 공유한 이번 세 구성의 점수를 함께 사용한다.

### 두 앙상블 사이의 점수 차이

두 앙상블의 점수 차이는 한 입력에서 발생했다.

> 박물관은 가고 싶지 않아요. 대신 전통 시장은 꼭 방문하고 싶어요.

두 조합 모두 박물관 회피와 전통 시장 필수 방문을 추출했다. 기존 조합은 박물관 회피의 `priority`를 정답과 같은 `preferred`로, 후보 조합은 `unspecified`로 반환했다. 엄격한 일치 평가에서 조건 한 개가 TP에서 FP·FN으로 바뀌어 F1이 4.0%p 달라졌다. 후보가 박물관 회피 의도를 전혀 찾지 못한 사례로 설명하지 않는다.

### 공통 검증 실패

두 조합 모두 다음 입력에서 최종 결과를 반환하지 못했다.

> 유제품이 들어간 음식은 피해야 합니다.

Gemini는 유제품 회피를 `required/explicit`으로 반환했지만 현재 근거 검사에서 필수 표현으로 인정되지 않아 조건이 거절됐다. Qwen 응답도 서비스 검증을 통과하지 못했다. 합성 정답은 이 회피를 `preferred/unspecified`로 두고 있어, 정답의 중요도 정책과 실제 한국어 표현·검증 규칙도 후속 점검 대상이다. 이번 비교 중에는 정답과 검증 규칙을 수정하지 않았다.

## 해석과 발표 문구

이번 고정 시험의 F1은 Gemini 단독 36.0%, 기존 Qwen 조합 52.0%, 추가 학습 후보 조합 48.0%였다. 두 앙상블의 차이는 중요도 라벨 한 개이며 26건은 9개 사례 묶음의 소규모 합성 시험이다. 실제 사용자 만족도·여행 일정 품질·새로운 일반 요청의 정확도로 확대 해석하지 않는다. 세 구성의 공통 검증 실패도 있어, 학습 외에 근거 검사와 정답 정책을 점검할 필요가 있다.

운영에는 기존 LoRA 어댑터를 유지했다. 이번 작업에서는 비교와 기록을 수행했으며 운영 어댑터를 교체하지 않았다. 서비스 준비 상태와 어댑터 체크섬도 비교 전후 대조했다.

발표에는 아래 문구를 사용할 수 있다.

> 합성 시험 26건에서 Gemini 단독과 두 앙상블을 비교했습니다. 두 Qwen은 같은 Docker 환경에서 단건 추론했고, Gemini 응답은 세 구성에 공유했습니다. F1은 Gemini 단독 36.0%, 기존 학습 Qwen 조합 52.0%, 추가 학습 후보 조합 48.0%였습니다. 두 앙상블의 차이는 중요도 라벨 한 건에서 발생했고, 세 구성 모두 유제품 회피 문장 검증에 실패했습니다. 실제 사용자 효과는 별도로 검증해야 합니다.

## 재현

설정은 [evaluation-paired.json](../configs/evaluation-paired.json), 실행 코드는 [evaluation/paired.py](../evaluation/paired.py)다. 키·가중치는 Git에 포함하지 않는다. 검증된 기반 모델과 기존 어댑터를 준비하고 추가 후보를 `artifacts/training/continued-20261115/adapter-best`에 복원한다. Dockerfile·Linux lock 파일로 이미지를 준비한다.

```powershell
New-Item -ItemType Directory -Force reports/runs/paired-20261115 | Out-Null
docker run --rm --gpus all --mount "type=bind,source=${PWD},target=/workspace,readonly" --mount "type=bind,source=${PWD}/reports/runs/paired-20261115,target=/evaluation" --workdir /workspace --env HF_HUB_OFFLINE=1 --env TRANSFORMERS_OFFLINE=1 woowangthon_team_17_ai-preference-qwen -m evaluation.paired qwen --output-dir /evaluation
python -m evaluation.paired gemini
python -m evaluation.paired ensemble
```

실제 실행 시 후보는 인접한 `ensemble-AI/artifacts/training/continued-20261115/adapter-best`에 있어, 그 디렉터리를 컨테이너의 `/candidate`에 읽기 전용 연결하고 `--candidate-path /candidate`를 사용했다. 모델은 위 SHA-256으로 식별한다. 기본 `reports/runs`는 Git 제외 대상이며 이번 공개 스냅샷은 `reports/paired-20261115-test.json`에 보존했다.

기록된 응답만으로 검증하려면 `python -m evaluation.paired replay`를 실행한다. 키·GPU·네트워크 호출 없이 공개 원자료를 읽고 실제 단독·결합 코드를 재생한다. Gemini 단독 26개와 두 앙상블 52개, 총 78개 결과의 조건·예약 내용과 집계가 일치함을 확인했으며, 예약의 실행별 임의 생성 ID는 비교에서 제외했다. 입력·정답과 전체 시험 분할도 원본 데이터에 대조한다. 새 Gemini 호출은 응답이 달라질 수 있으며, 이후 코드·모델을 바꾸면 새 출력 디렉터리를 사용한다.

## 코드 검증

Windows의 전체 AI 테스트에서 159개와 subtest 87개가 통과했다. 해당 환경에 Torch가 없어 제외됐던 학습 손실 검사와 CPU 공유 임베딩·출력층의 LoRA gradient 검사는 동일 Docker 이미지에서 각각 실행해 두 개 모두 통과했다. 따라서 두 환경을 합쳐 고유 테스트 161개를 확인했다. 같은 응답·재검토 캐시 공유, 전체 합성 시험 분할의 강제, 제공자 실패 포함을 검사했고 78개 결과의 오프라인 재생과 micro 집계식도 확인했다. Gemini 단독이 공유 응답만 사용하며 Qwen·외부 API를 호출하지 않는 점과, 단독 검증 실패의 누락 반영도 검사했다.

Docker에서 보완한 검사는 실제 큰 모델 재학습과 구분된다. completion-only loss의 위치 정렬과 CPU 공유층의 손실·gradient·가중치 갱신을 작은 고정 모델로 검증했다.
