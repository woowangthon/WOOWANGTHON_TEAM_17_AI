기존 Qwen은 복구한 Docker 서비스로 다시 실행했다. 후보는 같은 입력·추출 프롬프트로 Windows CUDA에서 greedy 배치 추론을 실행했다. 원래 서버는 단건 요청을 처리하고, 후보 실행은 최대 8건씩 생성한 뒤 서비스의 출력 검증과 앱의 결합 코드를 적용했다. Gemini는 `gemini-3.5-flash-lite` API를 사용했다. 같은 호출 결과를 단독 분석과 결합 분석에서 재사용했다. 호출 방식이 다르고 표본이 작아 점수 차이를 가중치 변경만의 효과로 해석하기는 어렵다. 기존 Qwen과 Gemini의 조합 전체를 이번에 다시 측정하지 않았다.

## 엑셀 234건에서 확인한 동작

234건 모두 Gemini와 Qwen의 실제 응답을 받았다. 결합 결과는 두 모델 사용 216건, 한 모델 사용 14건, 앱 검증 후 사용할 결과가 없었던 사례 4건이었다. 81건에서 충돌 재검토 호출이 있었고, 일시적 호출 제한·서비스 오류는 해당 재검토만 다시 실행했다. 양쪽이 원문을 읽었다는 사실만으로 최종 조건 반환이나 사용자 만족을 보장할 수 없다.

로컬 검토본은 기존 모델 결과에 사용자가 직접 매긴 점수 10개를 보존한다. 새 결과 234건의 점수와 의견은 구조 비교, 모델 보조 채점, 원문과 출력 대조로 작성한 AI 대리 평가다. 학습 예시를 포함한 엑셀 전체의 점수 분포는 일반화 성능 평가에 사용하지 않는다. 사람의 의견, 미공개 평가 요청, 개별 요청에 대한 모델 응답은 이 보고서의 공개 사례별 데이터에서 제외했다.
